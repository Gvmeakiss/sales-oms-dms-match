## 项目简介

本系统用于匹配销售订单、发货单和 SAP 发票三单数据，识别差异并进行分类分析。支持 OMS（订单管理系统）和 DMS（经销商管理系统）两种数据源。

**核心功能**：
- 三单数据匹配（订单 + 发货 + 发票）
- 差异计算和分类
- 按销售组织分组导出
- 自动生成汇总表和分类明细

**支持范围**：
- ✅ 2025年 1-9月数据匹配
- ✅ 2025年全年数据匹配
- ✅ OMS 数据匹配
- ✅ DMS 数据匹配（从SQL直接读取）

### 核心功能

1. **数据匹配**

   - 支持多数据源合并
   - 处理字段名变体和数据格式差异

2. **差异分析**

## 代码运行逻辑

### OMS 三单匹配流程

```
1. 数据加载
   ├─ 从 PKL 加载订单数据（或重新读取）
   ├─ 从 PKL 加载发货数据（或重新读取）
   └─ 从 PKL 加载发票数据（或重新读取）

2. 数据筛选
   ├─ 订单：筛选有效订单（非 OBSOLETE/CANCEL，2025年）
   ├─ 发货：筛选 2025年发货数据
   └─ 发票：筛选 ToB 发票（OMS，DMS销售单号为空）

3. 创建匹配键（order-item）
   ├─ 订单：sale_order_no + item_code（标准化）
   ├─ 发货：订单号（或主单号）+ 料号（标准化）
   └─ 发票：OMS销售单号 + 物料编码（标准化）
       └─ 如果缺 OMS，使用 DMS 映射：DMS销售单号 → external_order_no → sale_order_no

4. 数据聚合
   ├─ 订单：按 order-item 聚合（金额 sum，数量 sum，其他字段 first）
   ├─ 发货：按 order-item 聚合（数量 sum，其他字段 first）
   └─ 发票：按 order-item 聚合（金额 sum，数量 sum，其他字段 first）

5. 三单匹配
   ├─ 以发票为基准，左连接发货和订单
   └─ 生成匹配结果 DataFrame

6. 差异计算
   ├─ 订单-开票数量 = 订单数量 - 开票数量
   ├─ 发货-开票数量 = 发货数量 - 开票数量
   └─ 订单-发票金额 = 订单金额 - 开票金额

7. 分类标记
   ├─ 2.Not test：检查关键字段是否有缺失
   ├─ 1.1 完全匹配：数量差=0 且 金额差<1
   ├─ 1.2 金额不一致：金额差≥1 且 数量差=0
   ├─ 1.3 数量不一致：数量差≠0 且 金额差<1
   └─ 1.4 均不一致：数量差≠0 且 金额差≥1

8. 按销售组织分组
   ├─ 筛选 1240、1250、1260 三家公司
   └─ 其余公司单独分组

9. 导出 Excel
   ├─ 生成汇总表（各分类统计）
   ├─ 生成全部数据 sheet
   └─ 生成各分类 sheet（超限自动分多个 sheet）
```

### DMS 三单匹配流程

```
1. 数据加载
   ├─ 从 SQL 读取订单数据（1-9月 11列，10-12月 13列）
   ├─ 从 SQL 读取发货数据（7列，含错位纠错）
   └─ 从 Excel 读取发票数据（1-12月，concat join='outer'）

2. 数据筛选
   ├─ 订单：channel_name 含 DMS
   ├─ 发货：external_order_no 非空
   └─ 发票：发票类型含"标准发票"+"2B"，不含"退货"，DMS销售单号非空

3. 创建匹配键
   ├─ 订单：platform_order_no + item_code
   ├─ 发货：external_order_no + 料号
   └─ 发票：DMS销售单号 + 物料编码

4. 数据聚合（同 OMS）

5. 三单匹配（同 OMS）

6. 差异计算
   ├─ SAP-DMS订单金额 = 开票金额 - 订单金额
   └─ SAP-DMS发货数量 = 开票基本数量 - 发货数量

7. 分类标记（同 OMS）

8. 按销售组织分组（同 OMS）

9. 导出 Excel（同 OMS）
```

### 关键代码逻辑说明

#### 1. 匹配键创建

```python
# 标准化函数：去除 .0 后缀
def _norm_code(code):
    code_str = str(code)
    if code_str.endswith('.0'):
        code_str = code_str[:-2]
    return code_str

# 创建匹配键
df['order-item'] = df['sale_order_no'].astype(str) + _norm_code(df['item_code'])
```

#### 2. 数据聚合

```python
# 聚合字典：数值字段用 sum，描述字段用 first
agg_dict = {
    'pay_amount': 'sum',      # 金额求和
    'item_num': 'sum',         # 数量求和
    'sale_order_no': 'first',  # 订单号取第一个
    'item_code': 'first'       # 物料编码取第一个
}

# 执行聚合
pivot_order = df.groupby('order-item', as_index=False).agg(agg_dict)
```

#### 3. 差异计算

```python
# 转换为数值类型并计算差异
df['订单-开票数量'] = (
    pd.to_numeric(df['订单数量'], errors='coerce') - 
    pd.to_numeric(df['开票数量'], errors='coerce')
)
df['订单-发票金额'] = (
    pd.to_numeric(df['订单金额'], errors='coerce') - 
    pd.to_numeric(df['开票金额'], errors='coerce')
).round(2)
```

## 分类依据

### 分类逻辑说明

匹配结果根据**数据完整性和差异大小**进行分类：

#### 分类判断流程

```
1. 检查数据完整性
   ├─ 关键字段：订单金额、订单数量、发货数量、开票金额、开票数量
   └─ 如果任一字段缺失 → 标记为 "2.Not test"

2. 如果数据完整，计算差异
   ├─ 数量差异：订单-开票数量、发货-开票数量
   └─ 金额差异：订单-发票金额

3. 根据差异大小分类
   ├─ 数量差 = 0 且 金额差 < 1 → 1.1 完全匹配
   ├─ 数量差 = 0 且 金额差 ≥ 1 → 1.2 金额不一致
   ├─ 数量差 ≠ 0 且 金额差 < 1 → 1.3 数量不一致
   └─ 数量差 ≠ 0 且 金额差 ≥ 1 → 1.4 均不一致
```

### 分类详细说明

| 分类 | 条件 | 说明 | 示例 |
|------|------|------|------|
| **2.Not test** | 关键字段有缺失 | 订单、发货或发票数据不完整，无法进行匹配分析 | 订单金额为 NaN |
| **1.1 完全匹配** | 数量差=0 且 金额差<1 | 三单数据完全一致，无差异 | 订单100件1000元，开票100件1000元 |
| **1.2 金额不一致** | 数量差=0 且 金额差≥1 | 数量一致但金额有差异 | 订单100件1000元，开票100件1200元 |
| **1.3 数量不一致** | 数量差≠0 且 金额差<1 | 金额一致但数量有差异 | 订单100件1000元，开票90件900元 |
| **1.4 均不一致** | 数量差≠0 且 金额差≥1 | 数量和金额都有差异 | 订单100件1000元，开票90件1200元 |

### 阈值配置

分类阈值可在代码中配置：

```python
# 金额匹配阈值（默认 1.0）
AMOUNT_THRESHOLD = 1.0

# 数量匹配阈值（默认 0.01）
QUANTITY_THRESHOLD = 0.01
```

**注意**：
- 金额差异 < 1 视为匹配（考虑四舍五入误差）
- 数量差异 < 0.01 视为匹配（考虑小数精度）

### 分类代码实现

```python
# 检查关键字段是否有缺失
key_cols = ['订单金额', '订单数量', '发货数量', '开票金额', '开票数量']
df['2.Not test'] = df[key_cols].isna().any(axis=1)

# 分类逻辑（仅在数据完整时执行）
df['1.1完全匹配'] = (
    (df['订单-开票数量'].abs() < 0.01) &
    (df['发货-开票数量'].abs() < 0.01) &
    (df['订单-发票金额'].abs() < 1.0) &
    ~df['2.Not test']
)

df['1.2金额不一致'] = (
    (df['订单-发票金额'].abs() >= 1.0) &
    (df['订单-开票数量'].abs() < 0.01) &
    (df['发货-开票数量'].abs() < 0.01) &
    ~df['2.Not test']
)

df['1.3数量不一致'] = (
    ((df['订单-开票数量'].abs() >= 0.01) | (df['发货-开票数量'].abs() >= 0.01)) &
    (df['订单-发票金额'].abs() < 1.0) &
    ~df['2.Not test']
)

df['1.4均不一致'] = (
    ((df['订单-开票数量'].abs() >= 0.01) | (df['发货-开票数量'].abs() >= 0.01)) &
    (df['订单-发票金额'].abs() >= 1.0) &
    ~df['2.Not test']
)
```

## 常见问题

### Q1: 为什么所有数据都被标记为"2.Not test"？

**原因**：检查了所有列，包括可能包含 NaN 的额外字段。

**解决方案**：只检查关键字段（订单金额、订单数量、发货数量、开票金额、开票数量）。

**代码位置**：`match_oms_full_year.py` 第 314 行

```python
# 修改前（错误）
df_join['2.Not test'] = df_join.isna().any(axis=1)

# 修改后（正确）
key_cols = ['订单金额', '订单数量', '发货数量', '开票金额', '开票数量']
df_join['2.Not test'] = df_join[key_cols].isna().any(axis=1)
```

### Q2: 如何更新 PKL 缓存？

删除对应的 PKL 文件，下次运行时会重新生成。

```bash
# 删除所有缓存
rm -rf PKL/*.pkl

# 或删除特定缓存
rm PKL/oms_order_full_year.pkl
```

### Q3: Excel 文件超过行数限制怎么办？

系统会自动处理：
1. 超过 1,048,575 行时自动分多个 sheet
2. Sheet 命名：`全部数据_P1`、`全部数据_P2` 等

### Q4: 如何修改匹配阈值？

在代码中修改：

```python
# 金额匹配阈值（默认 1.0）
AMOUNT_THRESHOLD = 1.0

# 数量匹配阈值（默认 0.01）
QUANTITY_THRESHOLD = 0.01
```

### Q5: 内存占用过高怎么办？

**原因**：处理大数据量时内存占用较高（约 13-22GB）属于正常现象。

**优化建议**：
1. 使用 PKL 缓存避免重复读取
2. 分块处理大文件
3. 减少中间 DataFrame 的创建

### Q6: 如何只导出特定分类？

修改代码中的分类筛选逻辑：

```python
# 只导出完全匹配的数据
df_perfect = df_join[df_join['1.1完全匹配']].copy()
export_with_classification(df_perfect, '完全匹配.xlsx', '完全匹配')
```
